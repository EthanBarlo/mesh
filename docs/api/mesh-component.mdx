# `Mesh\Component`

Every Mesh component is a PHP class extending `EthanBarlo\Mesh\Component`. It declares the props passed to the frontend and the **id** that links to the JS component.

## Minimal component

```php
<?php

namespace App\Mesh;

use EthanBarlo\Mesh\Component;

class Counter extends Component
{
    public function props(): array
    {
        return [
            'start' => 0,
        ];
    }
}
```

## `props(): array`

Returns the associative array of props handed to the frontend component. Values must be JSON-serializable. Called once per render.

```php
public function props(): array
{
    return [
        'start' => $this->start,
        'label' => 'Clicks',
    ];
}
```

## `component(): string`

Returns the component **id** — a simple string like `Counter` or `Forms/Input`. By default it is
auto-derived from the class name, so you rarely write it yourself.

```php
// Default for App\Mesh\Counter — you don't need to write this.
public function component(): string
{
    return 'Counter';
}
```

## How the id is derived

The default `component()` derives the id from the class name relative to the `App\Mesh` namespace:
it strips the `App\Mesh\` prefix and replaces the remaining backslashes with forward slashes.

- `App\Mesh\Counter` → `Counter`
- `App\Mesh\Forms\Input` → `Forms/Input`

The JS side derives the identical id from the component's folder under the fixed `resources/js/mesh`
directory (`/resources/js/mesh/Forms/Input/index.tsx` → `Forms/Input`). Because `make:mesh`
StudlyCases both the class segments and the folder names, the two sides always agree.

You can override `component()` to return any id, but it must match an entry discovered by the
`import.meta.glob` in `app.ts`.

## Nested components

For `App\Mesh\Forms\Input`, the derived id is `Forms/Input`. The JS entry lives at
`resources/js/mesh/Forms/Input/index.tsx` and resolves to the same id automatically.

## How rendering works

1. Livewire renders `<livewire:mesh :component="...">`.
2. Mesh calls `component()` to get the id and `props()` to get the data.
3. The id is emitted to the runtime, which looks it up in the lazy component registry built from
   `import.meta.glob('/resources/js/mesh/**/index.{tsx,jsx}')`.
4. The runtime imports that component's code-split chunk on first render, then mounts it with the
   props using the renderer inferred from the entry's file extension.

## Case sensitivity

Component ids are case-sensitive. `App\Mesh\Counter` maps to the `Counter/` folder, not `counter/`. On case-insensitive filesystems (macOS) a mismatch can hide until it surfaces on Linux. Always keep the folder name byte-identical to the StudlyCase class name.

## Props lifecycle

Props are computed server-side in `props()` and serialized into the mount payload. They are not reactive after mount unless you re-render the Livewire component (which re-runs `props()` and re-mounts/updates the island).
