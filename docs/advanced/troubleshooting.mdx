---
title: Troubleshooting
description: Symptoms, causes and fixes for Mesh problems, with every error message quoted exactly so you can search for the one in your console.
---

Most Mesh problems fall into a handful of causes: Livewire is not started correctly, the two halves
of a component derive different ids, or a value is expected to sync when it is not wired to. Start
with the debug log, then find your symptom below.

## Turn on debug first

Pass `debug: true` to `initMesh`:

```ts title="resources/js/app.ts"
initMesh(Livewire, {
    renderers: [reactRenderer],
    debug: true,
});
```

The console then shows one line when Mesh starts and one per component Livewire initialises:

```text
Mesh |  Initialized Mesh {renderers: {…}, debug: true}
Mesh |  component.init | Counter {component: …}
```

- **No `Initialized Mesh` line:** `initMesh` never ran, or threw (look for an uncaught promise
  rejection just above).
- **`Initialized Mesh` but no `component.init | Counter`:** Livewire never initialised that
  component. The problem is on the Livewire side, not in your frontend code.
- **`component.init | Counter` but nothing renders:** the error is in the lines after it.

In the console, `Object.keys(window.Mesh.registry)` lists every id discovery found. Errors are
always logged, with or without `debug`.

## Nothing on the page works

<Accordions type="multiple">
<Accordion title="No errors, and no Livewire or Mesh behaviour at all" id="livewire-not-started">

**Cause.** `Livewire.start()` is never called, or the bundle that calls it is not on the page. When
the layout has `@livewireScriptConfig`, Livewire waits for you to start it.

**Fix.** End `resources/js/app.ts` with `Livewire.start()`, after `initMesh(...)`, and check the
layout loads it with `@vite([... 'resources/js/app.ts'])`.

</Accordion>
<Accordion title="Alpine warns it was initialized twice, and requests fail" id="missing-script-config">

```text
Alpine has already been initialized on this page. Calling
Alpine.start() more than once can cause problems.
```

**Cause.** `@livewireScriptConfig` is missing from the layout. Without it, Livewire's ESM build
starts itself on `DOMContentLoaded` (so your `Livewire.start()` makes it start twice) and has no
update URI or CSRF token to send requests with.

**Fix.** Put `@livewireScriptConfig` before `</body>` in every layout that loads the bundle. Do not
also use `@livewireScripts`.

</Accordion>
<Accordion title="Detected multiple instances of Livewire running" id="multiple-livewire">

```text
Detected multiple instances of Livewire running
Detected multiple instances of Alpine running
```

**Cause.** Livewire is loaded twice: once from your bundle and once from Livewire's own script tag
(`@livewireScripts`), or by importing a second copy.

**Fix.** Import Livewire only from `vendor/livewire/livewire/dist/livewire.esm` in `app.ts`, and use
`@livewireScriptConfig` (not `@livewireScripts`) in the layout.

</Accordion>
<Accordion title="Uncaught (in promise) Error: Mesh: … and no island mounts" id="registry-errors">

```text
Mesh: duplicate component id "Counter" derived from
"/resources/js/mesh/Counter/index.vue".

Mesh: cannot infer renderer for component entry "…"
(unknown extension "ts").

Mesh: source entry "…" does not live under a "resources/js/mesh/"
directory, so no component id can be derived. …
```

**Cause.** Building the registry failed, so `initMesh` stopped before it hooked into Livewire.
`window.Mesh` is never set, and no island on the page mounts. These appear as uncaught promise
rejections because `initMesh` is `async`. Livewire itself keeps working.

**Fix.**

- *Duplicate id:* two entries derive the same id, usually `index.tsx` and `index.vue` in one folder,
  or an app component and a package component. Keep one entry per folder; give package sources a
  `prefix`.
- *Unknown extension:* a `sources` glob matched a file Mesh cannot map to a renderer. Narrow the
  glob to `index.{tsx,jsx,vue,svelte}`.
- *Source entry outside a mesh directory:* every source entry needs `resources/js/mesh/` in its
  path. Move the files or fix the glob.

</Accordion>
<Accordion title="Warning: no components found under resources/js/mesh" id="no-components">

```text
Mesh: no components found under resources/js/mesh. Create one with
`php artisan make:mesh <Name>`.
```

**Cause.** Discovery found no `resources/js/mesh/**/index.{tsx,jsx,vue,svelte}` file. Either there
are none yet, the folder is somewhere else, or the entries are not named `index`.

**Fix.** Run `php artisan make:mesh <Name>` and follow the layout it creates. The folder is fixed at
`resources/js/mesh` and cannot be moved.

</Accordion>
</Accordions>

## One island does not mount

<Accordions type="multiple">
<Accordion title="Component is not registered" id="not-registered">

```text
Mesh: component "Forms/Input" is not registered. Known components:
Counter, Forms/TextInput.
```

**Cause.** The id from the PHP class (`component()`) has no frontend entry with the same id. Either
the two halves are named differently, or the entry was not discovered.

**Fix.** Compare the id in the message with the "Known components" list, character for character:

- The PHP class `App\Mesh\Forms\Input` needs `resources/js/mesh/Forms/Input/index.tsx` (or `.jsx`,
  `.vue`, `.svelte`).
- Case matters. `forms/input/` works on a case-insensitive macOS disk and fails on Linux.
- The entry must be called `index`. `Forms/Input/Input.tsx` is not discovered.
- In production, discovery happens at build time. A component added after the last
  `npm run build` does not exist until you build again.

`make:mesh` creates both halves with matching names, which avoids all of this.

</Accordion>
<Accordion title="Module has no default export" id="no-default-export">

```text
Mesh: component "Counter" module has no default export.
```

**Cause.** The entry file only has named exports.

**Fix.** `export default` the component from `index.tsx` or `index.jsx`. Vue and Svelte components
always have a default export.

</Accordion>
<Accordion title="Failed to render, renderer not found" id="renderer-not-found">

```text
Mesh: failed to render "Counter"
Error: Mesh renderer for "vue" not found
```

**Cause.** The entry's extension maps to a renderer (`vue` here) that is not in the `renderers` array
passed to `initMesh`.

**Fix.** Add it: `renderers: [reactRenderer, vueRenderer]`, and install the framework and its Vite
plugin (see [Vue](/docs/frameworks/vue#install) or [Svelte](/docs/frameworks/svelte#install)).

</Accordion>
<Accordion title="children or slots is reserved" id="reserved-props">

```text
Mesh: `children` is reserved for slot content — rename the prop
from props().

Mesh: `slots` is reserved for named slot content — rename the prop
from props().
```

**Cause.** In React and Svelte, slot content travels in the `children` and `slots` props. `props()`
returned a `children` key while the tag has slot content, or a `slots` key while it has named slots.
On first mount the message follows `Mesh: failed to render "<id>"`; on a later update it follows
`Mesh: failed to update props` or `Mesh: failed to update slots`.

**Fix.** Rename the key in `props()`, for example to `items`. Vue is not affected.

</Accordion>
<Accordion title="Mesh root element not found" id="no-mesh-root">

```text
Mesh: failed to render "Counter"
Error: Mesh root element not found
```

**Cause.** The component's HTML has no `.mesh-root` element, almost always because the PHP class
overrides `render()` or a published copy of the wrapper view was edited.

**Fix.** Remove the `render()` override; `Mesh\Component` renders the wrapper itself. See
[the rendered DOM](/docs/reference/blade#the-rendered-dom).

</Accordion>
<Accordion title="Unable to find component: [mesh::…]" id="unable-to-find-component">

```text
Unable to find component: [mesh::forms.inptu]
```

**Cause.** This is Livewire, at render time: no class matches the tag. The `mesh:` tag only resolves
classes in `App\Mesh` (in `app/Mesh`), with dots for sub-namespaces.

**Fix.** Check the spelling and the namespace: `<mesh:forms.input />` needs `App\Mesh\Forms\Input`.
Classes elsewhere are registered with Livewire and rendered with `<livewire:…>`.

</Accordion>
<Accordion title="LogicException: lives outside the [App\Mesh] namespace" id="outside-namespace">

```text
Mesh component [Acme\Widgets\Mesh\Chart] lives outside the [App\Mesh]
namespace; override component() to return an explicit id.
```

**Cause.** The default `component()` can only derive an id for classes under `App\Mesh`.

**Fix.** Override `component()` and return the frontend id, for example `'Acme/Chart'`. See
[Components in Composer packages](/docs/guides/packages).

</Accordion>
<Accordion title="useLivewireComponent must be used within a Mesh component" id="outside-island">

```text
useLivewireComponent must be used within a Mesh component
```

**Cause.** A Mesh hook or composable ran without the island's context. Either the component is
rendered somewhere Mesh did not mount it (a test, a component explorer, another app), or the page
has two copies of the framework or of `@mesh/vue` / `@mesh/svelte`, so the context key does not
match.

**Fix.** Provide the context in tests (see [Testing outside Mesh](/docs/reference/hooks#testing-outside-mesh)).
When `vendor/ethanbarlo/mesh` is a symlink, add `resolve.dedupe: ['vue']` or `['svelte']` to the Vite
config so only one copy is bundled.

</Accordion>
<Accordion title="The chunk fails to load" id="chunk-load">

```text
Failed to fetch dynamically imported module: …
```

**Cause.** This is the browser's message (Chrome's wording) for a lazy component chunk it cannot
load: a stale build or manifest, a deploy that removed old chunks while a tab was open, or a wrong
`@mesh` alias.

**Fix.** Rebuild and redeploy, and check the alias is `'@mesh': '/vendor/ethanbarlo/mesh/resources/js'`.
Mesh forgets a failed load, so the next attempt to mount the component tries again.

</Accordion>
<Accordion title="Works on macOS, breaks on Linux" id="case-sensitivity">

**Cause.** The class and folder differ only in case (`Counter.php` and `counter/`). macOS disks are
case-insensitive by default, Linux disks are not, and ids are compared exactly.

**Fix.** Make the folder path match the class path exactly, segment by segment, in StudlyCase.

</Accordion>
</Accordions>

## State and data

<Accordions type="multiple">
<Accordion title="Props look stale" id="stale-props">

**Cause.** `props()` runs on the server, on each render of the component. Nothing in the browser
updates it. It also does not run for actions that skip the render (`$this->skipRender()`,
`#[Renderless]`), and a value captured in `mount()` never changes.

**Fix.** Make sure a request re-renders this component. For values the browser edits, entangle a
public property instead of passing it as a prop. See [Props](/docs/guides/props).

</Accordion>
<Accordion title="Typed values never reach the server" id="deferred-entangle">

**Cause.** `useEntangle(key)` is deferred: changes stay in the browser until the next request.

**Fix.** That is usually what you want; the next `$call` carries them. If the server must react to
every change, use `useEntangle(key, true)`. To send now without an action, call `wire.$commit()`.

</Accordion>
<Accordion title="Changes to an entangled object or array do not sync" id="mutation">

**Cause.** The Vue and Svelte composables watch shallowly, and React state never notices in-place
mutation. Pushing to an array or setting a field on an object changes nothing Livewire can see.

**Fix.** Assign a new value: `columns.value = [...columns.value, card]` in Vue and Svelte,
`setColumns([...columns, card])` in React.

</Accordion>
<Accordion title="Cannot update locked property" id="locked">

```text
Cannot update locked property: [projectId]
```

**Cause.** The browser tried to set a property marked `#[Locked]`, through `useEntangle`, `$set` or
`wire.projectId = …`.

**Fix.** Do not entangle locked properties. Change them in a PHP action instead.

</Accordion>
<Accordion title="Validation messages do not appear" id="errors-missing">

**Cause.** `useErrorBag()` only carries errors whose key is a public property of the component.
Errors from `Validator::make()` with other keys, or keys like `form.email` that are not properties,
are dropped by Livewire. An empty bag also arrives as `[]`, not `{}`.

**Fix.** Validate the component's properties (`#[Validate]` with `$this->validate()` or
`validateOnly()`), and read errors by key: `errors.email?.[0]`.

</Accordion>
<Accordion title="$call succeeds even though validation failed" id="call-resolves-null">

**Cause.** When `$this->validate()` throws, Livewire handles it on the server and the request still
succeeds. The `$call` promise **resolves with `null`**; it does not reject.

**Fix.** Branch on the result (`if (result?.ok)`) and return an explicit payload from the action on
success. Keep `try`/`finally` for real request failures.

</Accordion>
<Accordion title="React: a $watch callback runs twice" id="strictmode-double">

**Cause.** React StrictMode, which the renderer always enables, runs effects twice in development.
An effect that calls `wire.$watch` without returning the unwatch function leaves two watchers.

**Fix.** Return it: `useEffect(() => wire.$watch('price', onPrice), [wire])`. See
[React gotchas](/docs/frameworks/react#strictmode-is-always-on).

</Accordion>
<Accordion title="React: a live entangle sends a request on page load" id="live-mount-request">

**Cause.** React's `useEntangle` writes its value back to Livewire after mount and after every
change. In live mode each write is a request.

**Fix.** Expected behaviour of the React hook (Vue and Svelte skip it). Use live mode only where the
server must see every change. See [React gotchas](/docs/frameworks/react#useentangle-writes-its-value-back).

</Accordion>
<Accordion title="await wire.$upload() returns before the upload finishes" id="upload-await">

**Cause.** Livewire's `$upload` returns nothing. The `Promise<void>` in the type does not wait for
anything.

**Fix.** Do the follow-up work in the `finish` callback (third argument). See the
[`$wire` API](/docs/reference/wire#uploads).

</Accordion>
</Accordions>

## Slots and layout

<Accordions type="multiple">
<Accordion title="Alpine or a Livewire component inside a slot does nothing" id="interactive-slot">

**Cause.** Slots reach the island as static HTML copied from a hidden holder. Nested Livewire
components and Alpine behaviour inside a slot are not supported.

**Fix.** Make the interactive part its own Mesh component, or pass the data as props and render it
in the framework. See [Limitations](/docs/advanced/limitations#slots-are-static-html).

</Accordion>
<Accordion title="Margins, padding or selectors on the wrapper have no effect" id="display-contents">

**Cause.** The wrapper elements Mesh renders use `display: contents`, so they have no box. Your
component's root element is laid out as a direct child of the tag's parent.

**Fix.** Style your component's own root element. Do not rely on `parent > *` selectors reaching it.
See [what display: contents means](/docs/reference/blade#what-display-contents-means-for-layout).

</Accordion>
</Accordions>

## Build and TypeScript

<Accordions type="multiple">
<Accordion title="Cannot find module '@mesh' or '@mesh/react'" id="ts-alias">

**Cause.** The `@mesh` alias exists in Vite but not in TypeScript (or the other way round).

**Fix.** Add the alias to both: `resolve.alias` in `vite.config.ts`, and `compilerOptions.paths` in
`tsconfig.json` (`@mesh` → `vendor/ethanbarlo/mesh/resources/js/index.ts`, `@mesh/*` →
`vendor/ethanbarlo/mesh/resources/js/*`). There is no npm package to install.

</Accordion>
<Accordion title="tsc reports errors inside vendor/ethanbarlo/mesh/resources/js/vue (or react, svelte)" id="ts-other-renderers">

**Cause.** Your `include` globs cover the whole vendored runtime, so `tsc` type-checks renderers for
frameworks you did not install.

**Fix.** Add the unused renderer folders to `exclude`, as the demo apps do (see the TypeScript step
on each [framework page](/docs/frameworks/react#install)).

</Accordion>
<Accordion title="Svelte: runes are not allowed in your module" id="svelte-runes">

**Cause.** A `.ts` file uses `$state`, `$derived` or `$effect`. Runes only compile in `.svelte`
files and in modules named `*.svelte.ts` or `*.svelte.js`.

**Fix.** Rename the module, for example `useBoard.ts` to `useBoard.svelte.ts`.

</Accordion>
<Accordion title="Vue or Svelte reactivity breaks between the renderer and your components" id="dedupe">

**Cause.** Two copies of the framework are bundled: one resolved from your app's `node_modules`, one
from next to the Mesh source. This happens when `vendor/ethanbarlo/mesh` is a symlink to a checkout
with its own `node_modules`.

**Fix.** Add `resolve.dedupe: ['vue']` (or `['svelte']`) to `vite.config.ts`.

</Accordion>
</Accordions>

Still stuck? Read the [Limitations](/docs/advanced/limitations) page in case you have hit one, then
open an issue on [GitHub](https://github.com/EthanBarlo/mesh/issues) with the console output from a
`debug: true` run.
