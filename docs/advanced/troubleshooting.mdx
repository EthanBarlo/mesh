# Troubleshooting

## Component doesn't mount

The most common cause is an **id mismatch** between PHP and JS.

### Check the id

The id derived by PHP must equal the id derived from the JS folder path. Both are simple strings.

- PHP: `App\Mesh\Counter` → `Counter` (strip `App\Mesh\`, backslashes become slashes).
- JS: `/resources/js/mesh/Counter/index.tsx` → `Counter` (keep what's after `resources/js/mesh/`,
  drop the extension and trailing `/index`).

If the class name and the folder name disagree (including case), the ids won't match and nothing
mounts. `make:mesh` keeps both in sync; mismatches usually come from renaming one side by hand.

## Glob doesn't match the component

Components are discovered by `import.meta.glob('/resources/js/mesh/**/index.{tsx,jsx}')` in `app.ts`.
A component is only registered if its entry is named `index.tsx` (or `index.jsx`) and lives under
`resources/js/mesh`. A file named anything else — or placed outside that directory — is ignored.
Check the folder layout and that the glob pattern includes your entry's extension.

## Renderer can't be inferred

The renderer comes from the entry file extension (`tsx`/`jsx` → React, `vue` → Vue, `svelte` →
Svelte). An unknown extension throws. Make sure the renderer key the extension maps to is present in
`initMesh({ renderers })`.

## Livewire not started

Mesh needs Livewire 4 running. Ensure `app.ts` ends with:

```ts
@livewireScriptConfig
Livewire.start()
```

## Case-sensitivity bugs

On macOS the filesystem is case-insensitive, so `Counter` and `counter` resolve the same. On Linux (production) they don't. Always match the case of the class name and the folder exactly — both are StudlyCase.

## Renderer not registered

If a component's inferred renderer key (e.g. `react`) isn't in `initMesh({ renderers })`, it won't mount. Check that the key is present.

## Props not updating

Props are computed server-side in `props()`. They only change when the Livewire component re-renders. If props look stale, verify the Livewire round-trip is happening.

## Still stuck?

- Double-check the PHP class name and the `resources/js/mesh/...` folder name produce the same id.
- Confirm the entry is `index.{tsx,jsx}` and matched by the `app.ts` glob.
- Verify the `@mesh` alias resolves in `vite.config.ts`.
- Check the browser console for dynamic-import errors when the chunk loads.
