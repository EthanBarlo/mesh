# Renderers

A **renderer** teaches Mesh how to mount a given framework's components. React ships built in; Vue and Svelte follow the same interface.

## Registering renderers

```ts
// resources/js/app.ts
import { initMesh } from '@mesh/runtime'
import { reactRenderer } from '@mesh/renderers/react'

initMesh({
  renderers: {
    react: reactRenderer,
  },
  components: import.meta.glob('/resources/js/mesh/**/index.{tsx,jsx}'),
})
```

## The renderer interface

A renderer implements `mount` and `unmount`:

```ts
export interface MeshRenderer {
  mount(el: HTMLElement, component: unknown, props: Record<string, unknown>): void
  unmount(el: HTMLElement): void
}
```

## Renderer is inferred from the file extension

Components do not declare a renderer. Mesh infers it from the entry file's extension:

- `index.tsx` / `index.jsx` → `react`
- `index.vue` → `vue`
- `index.svelte` → `svelte`

The inferred key must match a key in the `renderers` object passed to `initMesh`. If a `.vue`
component is discovered but no `vue` renderer is configured, the mount fails. An unknown extension
throws rather than silently defaulting.

## Built-in React renderer

The React renderer uses `createRoot` from `react-dom/client`.

## Vue and Svelte

To support other frameworks, register their renderers under the matching keys and add their entry
extensions to the glob so they are discovered:

```ts
initMesh({
  renderers: {
    react: reactRenderer,
    vue: vueRenderer,
    svelte: svelteRenderer,
  },
  components: import.meta.glob('/resources/js/mesh/**/index.{tsx,jsx,vue,svelte}'),
})
```

A component written as `index.vue` is inferred to use the `vue` renderer automatically.

## Choosing a renderer per component

A component's renderer is determined by its entry file extension. The PHP side is renderer-agnostic; it only carries the id and props.

## Adding a custom renderer

Implement the `MeshRenderer` interface and register it under a renderer key. Mesh maps a component to
that key via its file extension, so a custom renderer needs Mesh to recognise the corresponding
extension.

## Wiring renderers into `initMesh`

All renderers are passed in a single `initMesh({ renderers, components })` call at app boot. There is no per-component renderer config file; the renderer comes from the entry extension and the renderer map in `app.ts`.
