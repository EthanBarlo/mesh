title: initMesh()

`initMesh` builds the component registry and hooks Mesh into Livewire. Call it once, in the bundle
that starts Livewire, before `Livewire.start()`.

```ts title="resources/js/app.ts"
import { Livewire } from
    '../../vendor/livewire/livewire/dist/livewire.esm';
import { initMesh } from '@mesh';
import reactRenderer from '@mesh/react';
import vueRenderer from '@mesh/vue';

initMesh(Livewire, {
    renderers: [reactRenderer, vueRenderer],
    debug: import.meta.env.DEV,
});

Livewire.start();
```

## Signature

```ts
function initMesh(Livewire: any, config: Config): void;
```

| Parameter | Type | Description |
| --- | --- | --- |
| `Livewire` | `any` | The Livewire object from Livewire's ESM build. Mesh only calls `Livewire.hook()`. |
| `config` | `Config` | Renderers, extra sources and the debug flag. See below. |

`initMesh` does all of its work synchronously, before `Livewire.start()` runs:

1. It discovers every `resources/js/mesh/**/index.{tsx,jsx,vue,svelte}` file with
   `import.meta.glob`, adds the entries from `sources`, and builds the registry: one entry per
   component id, with the renderer type inferred from the file extension and a loader for its chunk.
   A bad entry is logged and skipped (see [Errors and warnings](#errors-and-warnings)).
2. It sets `window.Mesh` (see [window.Mesh](#windowmesh)).
3. It registers a `component.init` hook. For each Livewire component whose root has a
   `data-mesh-component` attribute, Mesh loads the component's chunk and, the first time an island
   of that type mounts, its renderer, in parallel. Then it mounts the island through the renderer
   and starts watching the slot holders. Components without the attribute are ignored.
4. It registers a `morph.updated` hook that passes fresh props to mounted islands.

It returns nothing and does not throw for configuration mistakes. A bad registry entry or an invalid
renderer is logged with `console.error` and skipped, so the rest of the page still mounts and your
`Livewire.start()` still runs. There is nothing to await, though `await initMesh(...)` is harmless.

    },

There are no other options. In particular, the component directory is fixed at `resources/js/mesh`
and cannot be configured.

The renderers you import in `app.ts` are small lazy descriptors, not the frameworks themselves.
React DOM, Vue or Svelte is fetched the first time an island of that kind mounts, so a page without
islands downloads no framework at all. Components are lazy too: each entry, with the libraries only
it imports, is its own chunk, loaded the first time that component renders. Mesh fetches a
component's chunk and its renderer in parallel. See
[Lazy renderers](/docs/reference/renderer#lazy-renderers).

| Extension | Renderer type | Built-in renderer |
| --- | --- | --- |
| `.tsx`, `.jsx` | `react` | `@mesh/react` |
| `.vue` | `vue` | `@mesh/vue` |
| `.svelte` | `svelte` | `@mesh/svelte` |

A renderer can claim more extensions with its `extensions` field, and a claim overrides the
built-in mapping. Discovery itself only globs the four extensions above, so entries with another
extension come in through `sources`. See
[Claiming a file extension](/docs/advanced/custom-renderers#claiming-a-file-extension).

## MeshSource

A source is the result of an `import.meta.glob` call that you write in the host app. Vite only
accepts literal glob patterns, which is why Mesh cannot glob package folders itself.

```ts
type GlobResult = Record<string, () => Promise<unknown>>;

type MeshSource =
    | GlobResult
    | { modules: GlobResult; prefix?: string };
```

```ts title="resources/js/app.ts"
initMesh(Livewire, {
    renderers: [reactRenderer],
    sources: [
        {
            modules: import.meta.glob(
                '/vendor/acme/widgets/resources/js/mesh/**/index.tsx',
            ),
            prefix: 'Acme',
        },
    ],
});
```

- **Bare form.** Pass the glob result directly. Ids are derived as for app components.
- **Wrapped form.** `{ modules, prefix }` puts every id from the source under `prefix`:
  `.../resources/js/mesh/Chart/index.tsx` becomes `Acme/Chart`.
- Every entry must have a `resources/js/mesh/` directory somewhere in its path. The id is the part
  after that marker, minus the extension and a trailing `/index`.
- Ids must be unique across the app and all sources. Use `prefix` to separate them. If two entries
  derive the same id, the first one keeps it: app components come before `sources`, and entries
  within one glob are in path order.
- Source entries are code-split and lazy-loaded exactly like app components.

The PHP half of a package component needs its own setup. See
[Components in Composer packages](/docs/guides/packages).

## Errors and warnings

Every message Mesh writes to the console, so you can search for it.

### At initialisation

| Message | Cause |
| --- | --- |
| ``Mesh: no components found under resources/js/mesh. Create one with `php artisan make:mesh <Name>`.`` | A warning. The registry is empty. |
| `Mesh: duplicate component id "Counter" derived from "…".` | Two entries derive the same id, for example `Counter/index.tsx` and `Counter/index.vue`, or an app component and a source entry. The message names the entry that was skipped. |
| `Mesh: cannot infer renderer for component entry "…" (unknown extension "ts").` | A source entry with an extension that neither the built-in mapping nor any renderer's `extensions` claims. |
| `Mesh: source entry "…" does not live under a "resources/js/mesh/" directory, so no component id can be derived. …` | A source glob matched a file outside a `resources/js/mesh/` directory. |
| ``Mesh: ignoring an invalid renderer (it needs a `type` and either `mount` or `load`).`` | Something in `renderers` is neither a renderer nor a lazy descriptor. |

These are logged with `console.error` while the registry is built, and the entry or renderer is
skipped. `window.Mesh` is still set and every other island mounts. A skipped component has no
entry, so an island that uses it logs `is not registered` (below).

### When a component mounts or updates

These are caught and logged with `console.error`. They affect one island; the rest of the page keeps
working.

| Message | Cause |
| --- | --- |
| `Mesh: component "Counter" is not registered. Known components: …` | The id from `component()` has no frontend entry. Compare it with the list in the message. |
| `Mesh: component "Counter" module has no default export.` | The entry file only has named exports. |
| `Mesh: failed to render "Counter"` | Loading the renderer or mounting threw. The underlying error is logged with it. |
| `Mesh renderer for "vue" not found` | Logged under the line above: a `.vue` entry exists but no Vue renderer was passed to `initMesh`. |
| `Mesh: the "vue" renderer's load() did not resolve to a renderer.` | Logged under the line above: a custom lazy descriptor's `load()` resolved to something without `mount`. A failed `load()` logs its own error here instead, and the next island tries again. |
| ``Mesh: `children` is reserved for slot content — rename the prop from props().`` | `props()` returned `children` while the tag has slots (React and Svelte). |
| ``Mesh: `slots` is reserved for named slot content — rename the prop from props().`` | `props()` returned `slots` while the tag has named slots (React and Svelte). |
| `Mesh root element not found` | The rendered wrapper has no `.mesh-root` element, usually because `render()` was overridden. |
| `Mesh: failed to update props` | A props update threw, for example a reserved-prop collision that appeared later. |
| `Mesh: failed to update slots` | A slot update threw. |
| `Failed to parse data-mesh-props:` | The props attribute was not valid JSON. The island gets `{}`. |

The [Troubleshooting](/docs/advanced/troubleshooting) page has fixes for each one.

## window.Mesh

After `initMesh` runs, `window.Mesh` holds the runtime's state. It is meant for debugging in the
browser console, not as an API.

<TypeTable
  type={{
    registry: {
      type: 'ComponentRegistry',
      description:
        'Every discovered component: id → { renderer, load }.',
    },
    resolved: {
      type: 'Record<string, Promise<any>>',
      description:
        'Component modules loaded so far, keyed by id. A failed load is removed so it can be retried.',
    },
    renderedComponents: {
      type: 'Record<string, RenderedComponent>',
      description:
        'Mounted islands, keyed by Livewire component id. An island is removed when Livewire tears it down.',
    },
    config: {
      type: 'object',
      description:
        'renderers (the renderers or lazy descriptors you passed, keyed by type) and debug (the flag you passed).',
    },
  }}
/>

```js
// In the browser console: which ids did discovery find?
Object.keys(window.Mesh.registry);

// Which renderer will mount "Forms/Input"?
window.Mesh.registry['Forms/Input'].renderer;
```
