# Installation

Mesh is a React + Livewire 4 islands bridge. The frontend ships inside the Composer package and is consumed through a Vite **alias** (`@mesh`), not npm.

## Requirements

- PHP 8.2+, Laravel 11+
- Livewire 4
- Node + Vite in the host app

## Step 1 — Require the package

```bash
composer require ethanbarlo/mesh
```

## Step 2 — Vite alias + plugins

Mesh auto-discovers components from `resources/js/mesh`, so they do **not** need individual Vite input
entries. Your `input` array only lists your real app entrypoints.

```ts
// vite.config.ts
import { defineConfig } from 'vite'
import laravel from 'laravel-vite-plugin'
import react from '@vitejs/plugin-react'

export default defineConfig({
  plugins: [
    laravel({
      input: [
        'resources/css/app.css',
        'resources/js/app.ts',
      ],
    }),
    react(),
  ],
  resolve: {
    alias: {
      '@mesh': '/vendor/ethanbarlo/mesh/resources/js',
    },
  },
})
```

## Step 3 — Configure `app.ts`

Register your renderers — that's all. Mesh auto-discovers every component under the fixed
`resources/js/mesh` directory: only `index.{tsx,jsx}` entries are picked up (co-located helper files
are ignored), and each becomes its own lazy, code-split chunk fetched on first render.

```ts
// resources/js/app.ts
import { Livewire, Alpine } from '../../vendor/livewire/livewire/dist/livewire.esm'
import { initMesh } from '@mesh'
import reactRenderer from '@mesh/react'

@livewireScriptConfig
initMesh(Livewire, {
  renderers: [reactRenderer],
  debug: true,
})

Livewire.start()
```

## Step 4 — Publish config (optional)

```bash
php artisan vendor:publish --tag=mesh-config
```

This writes `config/mesh.php`:

```php
return [
    'make' => [
        'renderer' => 'react',
    ],
];
```

The component directory is fixed at `resources/js/mesh` and is not configurable. The only published
option is the default renderer used by `make:mesh`.

## Step 5 — Create your first component

```bash
php artisan make:mesh Counter
```

This creates `app/Mesh/Counter.php` and `resources/js/mesh/Counter/index.tsx` (whose default export
is the component).

## Step 6 — Render in Blade

```blade
<mesh:counter />
```

## How the alias works

The `@mesh` alias points Vite at the package's `resources/js` directory inside `vendor/`. When you `import { initMesh } from '@mesh'`, Vite resolves it to the runtime inside `vendor/ethanbarlo/mesh/resources/js`. This keeps the runtime versioned with the PHP package.

## A simple id, derived identically on both sides

Every component has an **id** that is just a short string — `Counter`, or `Forms/Input` for a nested
component. It is derived the same way on each side:

- **PHP** strips the `App\Mesh\` prefix from the class name and replaces the remaining backslashes
  with forward slashes (`App\Mesh\Forms\Input` → `Forms/Input`).
- **JS** takes the discovered entry's path, keeps everything after `resources/js/mesh/`, drops the
  file extension and the trailing `/index` (`/resources/js/mesh/Forms/Input/index.tsx` → `Forms/Input`).

Because `make:mesh` StudlyCases both the class segments and the folder names, the ids match. The
renderer is inferred from the entry's file extension (`tsx`/`jsx` → React). See
[building components](guides/building-components.mdx).

## Step 7 — Production build

```bash
npm run build
```

Each component is emitted as a separate code-split chunk. The runtime imports a component's chunk on
first render, so only the components actually used on a page are loaded.
