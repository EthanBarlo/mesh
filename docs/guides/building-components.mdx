# Building components

A Mesh component has two parts: a PHP class and a framework component whose folder entry default-exports it. `make:mesh` scaffolds both, and Mesh auto-discovers every component under `resources/js/mesh` — no wiring required.

## Scaffold with `make:mesh`

```bash
php artisan make:mesh Counter
```

Creates:

- `app/Mesh/Counter.php`
- `resources/js/mesh/Counter/index.tsx` — the component (its **default export** is the component)

## The PHP class

```php
<?php

namespace App\Mesh;

use EthanBarlo\Mesh\Component;

class Counter extends Component
{
    public function props(): array
    {
        return ['start' => 0];
    }
}
```

## The React component

A component is a **folder** whose `index.{tsx,jsx}` default-exports it. Co-located helper files in the
same folder are ignored — only `index.{tsx,jsx}` is treated as the component entry.

```tsx
// resources/js/mesh/Counter/index.tsx
export default function Counter({ start }: { start: number }) {
  return <div>{start}</div>
}
```

That's it — no separate registration entry, and nothing to add to your Vite `input` array.

## Discovery

Components are not registered one by one. Mesh auto-discovers every component folder under
`resources/js/mesh` and code-splits each into its own lazy chunk, fetched on first render. `app.ts`
only registers renderers:

```ts
// resources/js/app.ts
initMesh(Livewire, {
  renderers: [reactRenderer],
  debug: true,
})
```

Add a new component just by creating its folder under `resources/js/mesh` — Mesh picks it up
automatically. There is no per-component Vite input and no `registerComponent` call.

## A simple id, derived identically on both sides

Each component is identified by a short **id** string — `Counter`, or `Forms/Input` for a nested
component — not a build path. Both sides derive it the same way:

- **PHP** strips the `App\Mesh\` prefix and replaces remaining backslashes with slashes
  (`App\Mesh\Forms\Input` → `Forms/Input`).
- **JS** takes the discovered entry's path, keeps everything after `resources/js/mesh/`, then drops
  the file extension and the trailing `/index` (`/resources/js/mesh/Forms/Input/index.tsx` → `Forms/Input`).

Because `make:mesh` StudlyCases both the class segments and the folder names, the ids match
automatically. The folder name must match the StudlyCase class name exactly — case matters on Linux
even if macOS hides a mismatch.

The renderer is inferred from the entry file extension: `tsx`/`jsx` → React, `vue` → Vue,
`svelte` → Svelte. An unknown extension throws rather than silently picking a default.

## Nested components

```bash
php artisan make:mesh Forms/Input
```

Creates `app/Mesh/Forms/Input.php` and `resources/js/mesh/Forms/Input/index.tsx`. The id is
`Forms/Input` on both sides, derived automatically.

## Props

`props()` returns a JSON-serializable array. Keys become the component's props:

```php
public function props(): array
{
    return ['start' => 5, 'label' => 'Hits'];
}
```

```tsx
export default function Counter({ start, label }: { start: number; label: string }) {
  return <button>{label}: {start}</button>
}
```

Props are computed on the server each render and passed into the component on mount.
