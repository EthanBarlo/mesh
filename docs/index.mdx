title: Introduction
description: Mesh renders React, Vue, and Svelte components as islands inside Livewire 4 views, with Livewire still owning the state.
---

Mesh lets a Livewire 4 app use a React, Vue, or Svelte component exactly
where it needs one. You write a Livewire component in PHP and a frontend
component beside it, and one Blade tag mounts the pair. Livewire keeps
owning state, validation, and actions. The frontend component renders and
talks back through a few small hooks. The rest of the page stays plain
Livewire and Blade, and there is no API layer to build.

## The mental model

A Mesh component is one component with two halves:

- **A PHP class** in `app/Mesh/` that extends `EthanBarlo\Mesh\Component`.
  That class extends `Livewire\Component`, so it *is* a Livewire component:
  public properties, actions, validation, `#[On]` listeners, and lifecycle
  hooks all work as usual.
- **A frontend component** at `resources/js/mesh/<Name>/index.tsx` (or
  `.jsx`, `.vue`, `.svelte`). Its default export is what gets rendered.

`<mesh:counter />` in any Blade view mounts both halves. Data crosses
between them on three channels.

| Channel | Direction | Use it for |
| --- | --- | --- |
| `props()` | server → frontend | Read-only data computed in PHP. A fresh snapshot on every render of the component. |
| `useEntangle(key)` | both ways | A public property both sides read and write: a form field, a counter, a selection. |
| `$wire`, via `useWire()` | frontend → server | Calling actions with `$call`, dispatching events, uploading files, watching properties. |

## A complete example

This is the `Counter` from the demo apps, minus the styling. The PHP half
owns `$count`. It captures the starting value once and sends it to the
frontend as a prop for the Reset button.

```php title="app/Mesh/Counter.php"
<?php

namespace App\Mesh;

use EthanBarlo\Mesh\Component;
use Livewire\Attributes\Modelable;

class Counter extends Component
{
    #[Modelable]
    public int $count = 0;

    public int $initialCount = 0;

    public function mount(): void
    {
        // Captured once: props() runs on every render.
        $this->initialCount = $this->count;
    }

    public function props(): array
    {
        return [
            'initialCount' => $this->initialCount,
        ];
    }
}
```

The frontend half entangles `count` and renders the buttons:

<Frameworks>
<Tab value="React">

```tsx title="resources/js/mesh/Counter/index.tsx"
import { useEntangle } from "@mesh/react";

export default function Counter({
    initialCount,
}: {
    initialCount: number;
}) {
    const [count, setCount] = useEntangle<number>("count");

    return (
        <div>
            <output>{count}</output>
            <button onClick={() => setCount(count - 1)}>-</button>
            <button onClick={() => setCount(initialCount)}>
                Reset
            </button>
            <button onClick={() => setCount(count + 1)}>+</button>
        </div>
    );
}
```

<Tab value="Vue">

```vue title="resources/js/mesh/Counter/index.vue"
<script setup lang="ts">
import { useEntangle } from "@mesh/vue";

const props = defineProps<{ initialCount: number }>();

const count = useEntangle<number>("count");
</script>

<template>
    <div>
        <output>{{ count }}</output>
        <button @click="count = count - 1">-</button>
        <button @click="count = props.initialCount">Reset</button>
        <button @click="count = count + 1">+</button>
    </div>
</template>
```

</Tab>
<Tab value="Svelte">

```svelte title="resources/js/mesh/Counter/index.svelte"
<script lang="ts">
    import { useEntangle } from "@mesh/svelte";

    let { initialCount }: { initialCount: number } = $props();

    const count = useEntangle<number>("count");
</script>

<div>
    <output>{count.value}</output>
    <button onclick={() => (count.value = count.value - 1)}>-</button>
    <button onclick={() => (count.value = initialCount)}>Reset</button>
    <button onclick={() => (count.value = count.value + 1)}>+</button>
</div>
```

Then render it from any Blade view:

```blade title="resources/views/dashboard.blade.php"
<mesh:counter :count="5" />

{{-- Or bind it to a property on the parent Livewire component --}}
<mesh:counter wire:model="count" />
```

`:count="5"` sets the public `$count` property, as it would on any
Livewire tag. Clicks update the island immediately. `useEntangle` is
deferred by default, so the new value reaches the server with the next
Livewire request rather than on every click (see
[Two-way state](/docs/guides/state)). `wire:model` works because `$count`
is marked `#[Modelable]`.

## Key ideas

- **An alias, not an npm package.** The JavaScript runtime ships inside the
  Composer package. A Vite alias, `@mesh`, points at
  `vendor/ethanbarlo/mesh/resources/js`, so the PHP and JavaScript halves of
  Mesh are always the same version. See
  [Installation](/docs/installation#the-mesh-alias).
- **One id, derived the same way on both sides.** PHP strips `App\Mesh\`
  from the class name (`App\Mesh\Forms\Input` becomes `Forms/Input`).
  JavaScript keeps the entry's path after `resources/js/mesh/`, minus the
  extension and `/index` (`Forms/Input/index.tsx` becomes `Forms/Input`).
  You never write the id by hand, and `php artisan make:mesh` creates both
  halves with matching names.
- **The file extension picks the renderer.** `.tsx` and `.jsx` mount with
  React, `.vue` with Vue, `.svelte` with Svelte. One app can use all three.
- **Zero-config discovery, one chunk per component.** `initMesh()` finds
  every `index.*` entry under `resources/js/mesh` with `import.meta.glob`.
  Each component becomes its own lazy chunk, fetched the first time a page
  renders it. There is nothing to register.
